## Version 10.1.0
![Date Badge](https://img.shields.io/badge/Publish-06%20September%202026-lightblue?logo=fastly&logoColor=white)
[![NuGet version](https://img.shields.io/badge/NuGet-v10.1.0-blue?logo=nuget)](https://www.nuget.org/packages/RA.Utilities.Api/10.1.0)

This release replaces the reflection-based endpoint registration with a compile-time, source-generated pipeline. Endpoints are now discovered by the `RA.Utilities.Api.Generators` analyzer (shipped inside the package) and registered without reflection, DI scanning, or manual registration lists.

<!-- truncate -->

### ⚠️ Breaking Changes

*   **`IEndpoint` redesigned**: The instance-based `IEndpoint` interface (`void MapEndpoint(IEndpointRouteBuilder)`) has been replaced by a static-abstract contract: `static abstract string GroupName { get; }` and `static abstract void MapEndpoint(RouteGroupBuilder group)`. Endpoint classes are now referenced statically by the generated registration code and no longer need to be instantiable.
*   **`EndpointExtensions` removed**: The reflection-based `AddEndpoints`/`MapEndpoints` extension methods have been removed. The `app.MapEndpoints()` call now maps every `IEndpointGroup` and `IEndpoint` implementation discovered at compile time by the source generator.
*   **Middleware extension classes consolidated into `MiddlewareExtensions`**: `DefaultHeadersMiddlewareExtensions`, `ExceptionHandlingExtensions`, `LoggingMiddlewareExtensions`, and `RequestContextLoggingMiddlewareExtensions` have been merged into a single `MiddlewareExtensions` class (same namespace, `RA.Utilities.Api.Extensions`). All extension methods keep their names, so no call-site changes are required unless code referenced the old class names directly.

### ✨ New Features

*   **`IEndpointGroup` interface**: Defines a shared route group (`static abstract string GroupName`, `static abstract RouteGroupBuilder MapGroup(IEndpointRouteBuilder app)`) that endpoints map into. Every group is created exactly once, before any endpoint is mapped.
*   **Compile-time endpoint registration**: A new Roslyn incremental source generator (`RA.Utilities.Api.Generators`) scans the consuming assembly for `IEndpointGroup` and `IEndpoint` implementations and emits the `MapEndpoints()` extension method (`RA.Utilities.Api.Extensions.HttpEndpointServiceCollectionExtensions`). No reflection, no runtime instantiation, no manual registration list.
*   **Compile-time group-name validation**: Group names are compared at compile time whenever they are compile-time constants:
    *   `EPMG001` — two `IEndpointGroup` implementations declare the same `GroupName`.
    *   `EPMG002` — an `IEndpoint` references a `GroupName` no group declares.
    *   `EPMG003` — a generic endpoint/group type (the generated code cannot supply a type argument).
    *   `EPMG004` — a private or file-local endpoint/group type that the generated code cannot reference.
    *   `EPMG005` — static interface members implemented explicitly (they cannot be invoked by the generated code).
    Names computed at runtime are still resolved correctly at startup; mismatches among those fail with a descriptive `InvalidOperationException` naming the endpoint type and the missing group key.

### 📝 Improvements

*   Nested and internal endpoint types are fully supported; types that merely inherit the static contract from a base class are not registered twice.
*   Updated `README.md` with the new `IEndpointGroup`/`IEndpoint` usage, compile-time validation behavior, and the simplified `app.MapEndpoints()` `Program.cs` flow.

## Version 10.0.6
![Date Badge](https://img.shields.io/badge/Publish-02%20August%202026-lightblue?logo=fastly&logoColor=white)
[![NuGet version](https://img.shields.io/badge/NuGet-v10.0.6-blue?logo=nuget)](https://www.nuget.org/packages/RA.Utilities.Api/10.0.6)

This release reorganizes extension methods into feature-specific classes and adds dynamic required header configuration.

<!-- truncate -->

### ⚠️ Breaking Changes

*   **Extension methods reorganized into feature-specific classes**: The generic classes `ApplicationBuilderExtensions`, `ServiceCollectionExtensions`, and `EndpointBuilderExtensions` have been replaced by `HttpLoggingExtensions`, `ValidationExtensions`, and a cleaned `EndpointExtensions`. All classes remain in the same namespace (`RA.Utilities.Api.Extensions`). **Migration**: No code changes are required for consuming projects — these are extension methods resolved by target type. If your code directly references the old class names (e.g., in unit tests or documentation), update those references. See the [Migration Guide](/RA.Utilities/nuget-packages/api/RA.Utilities.Api/migration-guides) for details.

*   **Response Models Consolidated**: All response model types from the now-deprecated `RA.Utilities.Api.Results` package have been merged into this package under the `RA.Utilities.Api.Results` namespace. The `RA.Utilities.Api.Results` NuGet package is no longer a dependency — update your package references and remove any direct dependency on `RA.Utilities.Api.Results`.

<!-- truncate -->

### ✨ New Features

*   **New Exception Mappings**: `ErrorResultMapper` and `ErrorResultResponse` now handle `TooManyRequestsException` (429), `ServiceUnavailableException` (503), and `GatewayTimeoutException` (504) with their dedicated response types.

*   **Extension Methods Added**: `AddRaExceptionHandling()` and `UseRaExceptionHandling()` are now available as convenience extension methods on `IServiceCollection` and `IApplicationBuilder`, matching the documented API.

### ✨ New Features

*   **`DefaultHeadersOptions.RequiredHeaders`**: The default headers middleware now supports dynamic configuration of required HTTP headers via a `RequiredHeaders` collection. Each entry uses the new `RequiredHeaderDefinition` model with `Name`, `AutoGenerate`, `EchoInResponse`, and `ErrorMessage` properties.
*   **`RequiredHeaderDefinition` model**: New POCO class in `RA.Utilities.Api.Options` for defining per-header enforcement behavior.

### 📝 Improvements

*   **`DefaultHeadersMiddleware` updated**: Now iterates over `DefaultHeadersOptions.RequiredHeaders` instead of hardcoding `x-request-id`. Multiple missing headers are collected and returned in a single `400 Bad Request` response. Default configuration preserves backward compatibility.
*   **`HttpLoggingExtensions` class**: `AddHttpLoggingMiddleware` and `UseHttpLoggingMiddleware` are now paired in a single feature-focused class.
*   **`EndpointExtensions` cleaned**: The `Validate<TModel>()` method was extracted to `ValidationExtensions`, keeping `EndpointExtensions` focused on endpoint discovery and mapping.

*   **Improved Logging**: `GlobalExceptionHandler` now logs client errors (4xx) at `Warning` level and server errors (5xx) at `Error` level, reducing log noise from expected client behavior.

*   **Consistency & Polish**:
    *   Renamed static helper class `SuccessResponse` → `SuccessResult` to resolve the naming collision with `SuccessResponse<T>`.
    *   Removed unnecessary `where TResult : new()` constraints on `SuccessResult` helper methods.
    *   `MapEndpoints` now returns `WebApplication` instead of `IApplicationBuilder` for better fluent chaining.
    *   Error dispatcher now uses `BaseResponseCode` constants instead of hardcoded `StatusCodes` literals.
    *   Removed stale TODO comments and `<remarks>` blocks from `EndpointExtensions`.

*   **README updated**: Added documentation for `Validate<TModel>()`, `HttpLoggingMiddleware`, and `DefaultHeadersMiddleware` features.
*   **Refined Documentation**: Updated `README.md` to reflect all API changes, including corrected method signatures, new response type mappings, and the consolidation of response models.
