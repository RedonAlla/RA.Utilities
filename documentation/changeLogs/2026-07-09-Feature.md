## Version 10.0.2
![Date Badge](https://img.shields.io/badge/Publish-09%20August%202026-lightblue?logo=fastly&logoColor=white)
[![NuGet version](https://img.shields.io/badge/NuGet-10.0.2-blue?logo=nuget)](https://www.nuget.org/packages/RA.Utilities.Feature/10.0.2)

### ✨ New Features

*   **`RequestHandler` Abstract Base Classes** — New `RequestHandler<TRequest>` and `RequestHandler<TRequest, TResponse>` in the `RA.Utilities.Feature.Handlers` namespace. These provide built-in `ILogger`-based logging for request start/finish and automatic exception-to-`Result.Failure` conversion. Derived classes override `HandleAsync` and focus solely on business logic — no boilerplate `try-catch` blocks.

*   **Configurable Notification Retry** — `NotificationRetryBehavior<TNotification>` now accepts `maxRetries` (default: 3) and `baseDelayMilliseconds` (default: 200) via its constructor, with `ArgumentOutOfRangeException` validation on both parameters.

### 🐛 Bug Fixes

*   **Mediator** — Removed unreachable null-coalescing `?? throw` after `GetRequiredService<T>()` in both `Send` overloads. `GetRequiredService` never returns `null`.
*   **Mediator** — `Publish` now isolates each notification handler in its own `try-catch`. Previously, one failing handler would prevent all subsequent handlers from executing. Failures are logged and execution continues.
*   **Mediator** — `Publish` returns immediately when no handlers are registered for a notification type, skipping unnecessary behavior resolution.
*   **`NotificationMetricsBehavior`** — Replaced the `Stopwatch` instance field with a local `Stopwatch.StartNew()` variable, eliminating a thread-safety hazard.
*   **`ValidationBehavior`** — Both constructors now guard against `null` with `?? Array.Empty<IValidator<TRequest>>()`, preventing `NullReferenceException` in edge cases.
*   **`LoggingBehavior<TRequest>`** — The no-response variant now logs consistently with the two-param variant (`"Start. Request: {...}"` / `"Finished. Result: {...}"`).
*   **`IMediator` XML doc** — Fixed typo: `"reques"` → `"request"`.

### 📖 Documentation

*   Comprehensive README rewrite covering the custom mediator, base handlers, pipeline behaviors, notification system, and all built-in behaviors with notification usage examples.
*   New Docusaurus sections: `Handlers/` and `Builders/` with detailed API documentation.
*   Fixed stale code samples throughout — removed MediatR references, corrected generic arity, and updated registration examples to use the fluent builder API.
