## Version 10.1.0
![Date Badge](https://img.shields.io/badge/Publish-10%20August%202026-lightblue?logo=fastly&logoColor=white)
[![NuGet version](https://img.shields.io/badge/NuGet-10.1.0-blue?logo=nuget)](https://www.nuget.org/packages/RA.Utilities.Feature/10.1.0)

### 💥 Breaking Change: `PipelineContext` is now generic `PipelineContext<T>`

The dictionary-based `PipelineContext` class (with `Set<T>()`/`Get<T>()`) has been replaced with a **strongly-typed** `PipelineContext<T>` where `T` is a user-defined class with a parameterless constructor.

**Why:**
- Compile-time safety — typos in context keys are caught by the compiler instead of silently returning `default`
- No boxing — value types don't need to be boxed/unboxed
- IntelliSense — context properties are discoverable via autocompletion in any IDE
- Simpler API — `ctx.Data.CorrelationId` instead of `ctx.Get<string>("correlationId")`

**Migration from v10.0.1:** Define a class for your context data, use `PipelineContext<MyContext>` instead of `PipelineContext`, and access properties via `.Data`. Existing `Send`/`Publish` calls without a context type parameter continue to compile unchanged — the context type parameter is entirely opt-in. See the [migration guide](https://redonalla.github.io/RA.Utilities/nuget-packages/Application/Feature/migration-guides) for detailed before/after examples.

### ✨ New Features

*   **Typed `PipelineContext<T>`** — strongly-typed data carrier flowing through the entire pipeline. User-defined `T` carries context data. Each `Send`/`Publish` call gets an isolated instance. No dictionaries, no magic strings, no boxing.
*   **Context-aware `IMediator` overloads** — `Send<TRequest, TResponse, TContext>()`, `Send<TRequest, TContext>()`, and `Publish<TNotification, TContext>()`.
*   **Generic context methods on all pipeline interfaces** — `IPipelineBehavior`, `INotificationBehavior`, `IRequestHandler`, and `INotificationHandler` now have generic `HandleAsync<TContext>(...)` overloads with default implementations for full backward compatibility.
*   **`RequestHandler` base classes** — new `HandleAsync<TContext>(...)` protected virtual method. Derived handlers can override to consume typed context data; default delegates to the non-context abstract method.
*   **`RequestHandler<TRequest>` and `RequestHandler<TRequest, TResponse>` abstract base classes** — provide built-in `ILogger`-based logging for request start/finish and automatic exception-to-`Result.Failure` conversion. Derived classes override `HandleAsync` and focus solely on business logic.
*   **Configurable `NotificationRetryBehavior`** — now accepts `maxRetries` (default: 3) and `baseDelayMilliseconds` (default: 200) via its constructor, with `ArgumentOutOfRangeException` validation.

### 🐛 Bug Fixes

*   **Mediator** — Removed unreachable null-coalescing `?? throw` after `GetRequiredService<T>()` in both `Send` overloads.
*   **Mediator** — `Publish` now isolates each notification handler in its own `try-catch`. One failing handler no longer prevents subsequent handlers from executing.
*   **Mediator** — `Publish` returns immediately when no handlers are registered for a notification type, skipping unnecessary behavior resolution.
*   **`NotificationMetricsBehavior`** — Replaced the `Stopwatch` instance field with a local `Stopwatch.StartNew()` variable, eliminating a thread-safety hazard.
*   **`ValidationBehavior`** — Both constructors now guard against `null` with `?? Array.Empty<IValidator<TRequest>>()`.
*   **`LoggingBehavior<TRequest>`** — The no-response variant now logs consistently with the two-param variant (`"Start. Request: {...}"` / `"Finished. Result: {...}"`).
*   **`IMediator` XML doc** — Fixed typo: `"reques"` → `"request"`.
*   All built-in behaviors now pass the typed `PipelineContext<T>` through the delegate chain.

### 📖 Documentation

*   Comprehensive README rewrite covering the custom mediator, base handlers, pipeline behaviors, notification system, typed pipeline context, and all built-in behaviors.
*   New Docusaurus sections: `Handlers/`, `Builders/`, and `Models/PipelineContext`.
*   Fixed stale code samples throughout — removed MediatR references, corrected generic arity, and updated registration examples to use the fluent builder API.
*   New migration guide covering v10.0.1 → v10.1.0 with detailed before/after examples.
*   New troubleshooting entries for common context-related issues.
