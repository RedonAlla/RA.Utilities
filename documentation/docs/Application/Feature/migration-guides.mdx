# Migration Guides

## v10.0.1 → v10.1.0

### Breaking Change: `PipelineContext` is now generic `PipelineContext<T>`

The dictionary-based `PipelineContext` (with `Set<T>()`/`Get<T>()`/`TryGetValue<T>()`) has been replaced with a strongly-typed `PipelineContext<T>` where `T` is a user-defined class with a parameterless constructor.

If you were not using `PipelineContext` in v10.0.1, this change does not affect you — all existing code compiles unchanged.

### Why this change?

- **Compile-time safety** — typos in context keys are caught by the compiler instead of silently returning `default`
- **No boxing** — value types don't need to be boxed/unboxed
- **IntelliSense** — context properties are discoverable via autocompletion
- **Simpler API** — `ctx.Data.CorrelationId` instead of `ctx.Get<string>("correlationId")`

### Migration Steps

#### 1. Define a context class

**Before (v10.0.1 — hypothetical, as PipelineContext didn't exist):**

```csharp
// No context API available in v10.0.1
```

**After (v10.1.0):**

```csharp
public class MyPipelineContext
{
    public string? CorrelationId { get; set; }
    public int? UserId { get; set; }
    public System.Diagnostics.Stopwatch? Timer { get; set; }
}

var ctx = new PipelineContext<MyPipelineContext>();
ctx.Data.CorrelationId = "abc-123";
var id = ctx.Data.CorrelationId;
```

#### 2. Write context-aware behaviors

```csharp
public class CorrelationIdBehavior<TRequest, TResponse> : IPipelineBehavior<TRequest, TResponse>
    where TRequest : IRequest<TResponse>
{
    // Required: implement the non-context method for backward compatibility
    public Task<Result<TResponse>> HandleAsync(
        TRequest request, RequestHandlerDelegate<TResponse> next, CancellationToken ct)
        => HandleAsync(request, _ => next(), new PipelineContext<MyPipelineContext>(), ct);

    // Override the generic context-aware method
    public async Task<Result<TResponse>> HandleAsync<TContext>(
        TRequest request, RequestHandlerContextDelegate<TResponse, TContext> next,
        PipelineContext<TContext> context, CancellationToken ct)
        where TContext : class, new()
    {
        if (context is PipelineContext<MyPipelineContext> ctx)
            ctx.Data.CorrelationId = Guid.NewGuid().ToString();
        return await next(context);
    }
}
```

#### 3. Write context-aware handlers

```csharp
public class MyHandler : RequestHandler<MyCommand, Result<Data>>
{
    public MyHandler(ILogger<MyHandler> logger) : base(logger) { }

    // Override the abstract method for basic use
    public override Task<Result<Data>> HandleAsync(MyCommand request, CancellationToken ct)
    {
        // Business logic without context
    }

    // Override the virtual method to consume typed context
    protected override async Task<Result<Data>> HandleAsync<TContext>(
        MyCommand request, PipelineContext<TContext> context, CancellationToken ct)
        where TContext : class, new()
    {
        if (context is PipelineContext<MyPipelineContext> ctx)
            _logger.LogInformation("CorrelationId: {Id}", ctx.Data.CorrelationId);
        return await base.HandleAsync(request, context, ct);
    }
}
```

#### 4. Send requests with typed context

```csharp
// Without context — still works, unchanged from v10.0.1
var result = await mediator.Send<MyCommand, Result<Data>>(command);

// With typed context — new in v10.1.0
var ctx = new PipelineContext<MyPipelineContext>();
ctx.Data.UserId = 42;
var result = await mediator.Send<MyCommand, Result<Data>, MyPipelineContext>(command, ctx);

// Publish notifications with typed context
await mediator.Publish<OrderPlaced, MyPipelineContext>(notification, ctx);
```

### What Else is New in v10.1.0

These changes are additive and do not require migration:

| Change | Impact |
|---|---|
| `RequestHandler` base classes | Opt-in — inherit from `RequestHandler<TRequest, TResponse>` instead of implementing `IRequestHandler` directly to get free logging and exception handling |
| Configurable `NotificationRetryBehavior` | Opt-in — constructor now accepts `maxRetries` and `baseDelayMilliseconds`; defaults match v10.0.1 behavior |
| Per-handler exception isolation in `Publish` | Automatic — one failing handler no longer prevents others from executing |
| Thread-safe `NotificationMetricsBehavior` | Automatic — `Stopwatch` moved from instance field to local variable |
| `ValidationBehavior` null guard | Automatic — prevents `NullReferenceException` in edge cases |
| Consistent `LoggingBehavior` messages | Automatic — no-response variant now logs consistently |

### No changes needed for existing v10.0.1 code

Existing `Send<TRequest, TResponse>(...)` and `Publish<TNotification>(...)` calls compile unchanged. The context type parameter is entirely opt-in. Internally, the Mediator uses a private marker type when no user-defined context is provided.

### Registration Pattern (unchanged)

The fluent builder registration API is unchanged from v10.0.1:

```csharp
builder.Services.AddMediator();

builder.Services
    .AddFeature<CreateProductCommand, Result<int>, CreateProductHandler>()
    .AddDecoration<LoggingBehavior<CreateProductCommand, Result<int>>>()
    .AddValidator<CreateProductCommandValidator>();
```

## v10.0.0-rc.2 → v10.0.0 / v10.0.1

### API Stability

Starting with v10.0.0, the package API is considered stable. The custom mediator, pipeline behaviors, notification system, and fluent builder registration API are the supported patterns.

Key differences from the rc.2 release notes (which incorrectly referenced MediatR):

| rc.2 Documentation (incorrect) | Actual API (v10.0.0+) |
|---|---|
| `builder.Services.AddMediatR(cfg => ...)` | `builder.Services.AddMediator()` |
| `services.AddTransient(typeof(IPipelineBehavior<,>), typeof(ValidationBehavior<,>))` | `.AddValidator<TValidator>()` on the fluent builder |
| `services.AddValidatorsFromAssembly(...)` | Validators are registered per-feature via `AddValidator<T>()` |

### Registration Pattern (v10.0.0+)

```csharp
builder.Services.AddMediator();

builder.Services
    .AddFeature<CreateProductCommand, Result<int>, CreateProductHandler>()
    .AddDecoration<LoggingBehavior<CreateProductCommand, Result<int>>>()
    .AddValidator<CreateProductCommandValidator>();
```
