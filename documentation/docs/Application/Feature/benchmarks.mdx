# Benchmarks

The `RA.Utilities.Feature.Benchmarks` project compares the generated mediator against **MediatR 12.5** (and, historically, against the pre-v11.1.0 runtime mediator) using [BenchmarkDotNet](https://benchmarkdotnet.org/), scenario for scenario.

## 🎯 Methodology

- **Equal lifetimes.** Both sides register their request handlers **scoped**, matching this package's documented lifetime, so the comparison measures dispatch machinery, not DI lifetime bookkeeping.
- **Fresh scope per iteration.** Each iteration resolves the mediator from a new `IServiceScope`, mirroring per-request semantics.
- **Same payloads.** Both sides share the same `PongResponse` and request shapes; handlers return a plain response (no `Result` wrapper).
- **Same pipeline depth.** Depth is modeled with distinct request types per depth on both sides (depth is fixed by the DI registrations).
- **Hardware.** Apple M1, .NET 10, default job (≈15 warmup + ≈20 target iterations per benchmark); all classes run in the same session so machine conditions are identical within a table. Absolute numbers shift between sessions — compare **within** a run.

## 📊 Results (send shapes)

| Scenario | MediatR | Generated `MediatorImpl` (concrete) | Delta |
|---|---|---|---|
| Send, 0 behaviors | 165.0 ns / 568 B | **144.9 ns / 504 B** | −12% time, −11% alloc |
| Send, 3 behaviors | 251.7 ns / 1096 B | **207.3 ns / 1000 B** | −18% time, −9% alloc |
| Send, void | 146.6 ns / 472 B | **129.2 ns / 408 B** | −12% time, −14% alloc |
| Send, with context | 179.0 ns / 624 B | 207.5 ns / 872 B | +16% time, +248 B (see note) |

Additional generated-mediator shapes (no MediatR counterpart at the same pipeline depth):

| Path | Mean | Allocated |
|---|---|---|
| `IMediator.Send<TRequest, TResponse>(...)` (interface-typed) | 186.7 ns | 504 B |
| `MediatorImpl.Send((object)request)` (object dispatch) | 146.8 ns | 504 B |

MediatR reference points: 1 behavior at 211.2 ns / 808 B (the generated mediator runs a full **3-behavior** pipeline faster than that) and 3 void behaviors at 240.8 ns / 1000 B.

### Why the generated mediator wins

- **Concrete handler injection** — the generator registers handlers as themselves, and the generated `Send` resolves `PingHandler` directly and calls it (devirtualized), where MediatR walks a runtime `request.GetType()` dictionary into a cached wrapper and resolves through a non-generic `GetService(Type)` path.
- **No delegate chain without behaviors** — with an empty pipeline the handler is invoked directly.
- **Hand-rolled reverse loop** — behavior composition avoids the LINQ `Reverse().Aggregate(...)` iterator and closure chain MediatR pays on every call.

### The context caveat

The context row is not apples-to-apples: MediatR has no `PipelineContext<T>`, so its benchmark carries the context data **inside the request record** (pre-created, zero extra allocation), while the generated mediator allocates a `PipelineContext<T>` and the `T` instance per call and runs a real context-aware behavior. On pure dispatch the two are at parity in that shape.

## 🛠️ Running the benchmarks

```bash
# From the repository root; the env var disables the NuGet vulnerability audit
# for BenchmarkDotNet's inner autogenerated build.
NuGetAudit=false dotnet run -c Release \
  --project Benchmarks/RA.Utilities.Feature.Benchmarks/RA.Utilities.Feature.Benchmarks.csproj \
  --filter '*SendBenchmarks*' --job default
```

- `--filter '*MediatrSendBenchmarks*'` — the MediatR comparison only.
- `--filter '*GeneratedMediatorSendBenchmarks*'` — the generated mediator only.
- `--job short` for a quick smoke run.

The benchmark sources live in `Benchmarks/RA.Utilities.Feature.Benchmarks/`:

| Folder | Contents |
|---|---|
| `Shared/` | `DiHost` scope factory and the shared payload types |
| `Comparison/` | MediatR handlers, behaviors, requests, and benchmarks |
| `Feature/` | The generated-mediator scenarios: handlers (registered explicitly — generic handler types are not auto-registered), closed no-op behaviors (auto-registered by the generator), and the benchmark classes |

## 🧠 Summary

At equal lifetimes, the generated mediator is **12-18% faster with 9-14% fewer allocations** than MediatR across the send shapes, interface-typed dispatch is within a few percent of the concrete path, and object-based dispatch costs the same as a monomorphic send. See the [Generated Mediator](./generated-mediator) guide for the dispatch matrix behind these numbers.
