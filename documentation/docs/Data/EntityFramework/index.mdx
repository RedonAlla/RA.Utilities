# RA.Utilities.Data.EntityFramework

[![NuGet version](https://img.shields.io/nuget/v/RA.Utilities.Data.EntityFramework.svg?logo=nuget&label=NuGet)](https://www.nuget.org/packages/RA.Utilities.Data.EntityFramework/)
[![NuGet Downloads](https://img.shields.io/nuget/dt/RA.Utilities.Data.EntityFramework.svg?logo=nuget)](https://www.nuget.org/packages/RA.Utilities.Data.EntityFramework/)
[![Codecov](https://codecov.io/github/RedonAlla/RA.Utilities/graph/badge.svg)](https://codecov.io/github/RedonAlla/RA.Utilities)
[![Publish NuGet](https://github.com/RedonAlla/RA.Utilities/actions/workflows/publish-nuget.yml/badge.svg)](https://github.com/RedonAlla/RA.Utilities/actions/runs/20216149254)
[![GitHub license](https://img.shields.io/github/license/RedonAlla/RA.Utilities)](https://github.com/RedonAlla/RA.Utilities/blob/main/LICENSE)

The primary purpose of the `RA.Utilities.Data.EntityFramework` package is to provide concrete implementations of the data access abstractions defined in
[`RA.Utilities.Data.Abstractions`](../Abstractions/index.mdx).
It uses Entity Framework Core to build a ready-to-use, generic data access layer.

In short, it's the "engine" that connects your application's abstract data access patterns (like the Repository and Unit of Work) to a real database using EF Core.

## 🔑 Key Components and Benefits
This package accelerates the setup of a data access layer by providing several key components:

#### 1. Generic Repository Implementations:
* **[`RepositoryBase<T, TKey>`](./RepositoryBase.md)**: A full implementation of [`IRepositoryBase<T, TKey>`](../Abstractions/IRepositoryBase.md) that provides complete CRUD (`Create`, `Read`, `Update`, `Delete`) functionality out of the box.
* **[`ReadRepositoryBase<T, TKey>`](./ReadRepositoryBase.md)**: A read-only repository that is optimized for querying data. It uses `AsNoTracking()` by default for better performance, which is ideal for CQS (Command Query Separation) patterns.
* **[`WriteRepositoryBase<T, TKey>`](./WriteRepositoryBase.md)**: A write-only repository for command operations (`Add`, `Update`, `Delete`).

#### 2. Dependency Injection Extensions:
It provides extension methods like `AddRepositoryBase()` to simplify the registration of these generic repositories in your application's DI container.

#### 3. Value Object Mapping:
The [`Conventions`](./Conventions/ValueObjectConverters) namespace provides EF Core value converters that persist the value objects of [`RA.Utilities.Core.ValueObjects`](../../core/RA.Utilities.Core.ValueObjects/index.mdx) — `Email`, `Currency`, `SSN`, and `Money`. The [`HasMoney()`](./Extensions/MoneyConventionExtensions) extension maps a `Money` property to two separate columns (decimal `Amount` + string `Currency`) as an EF Core complex property, while [`MoneyConverter`](./Conventions/ValueObjectConverters) stores it as a single JSON string column.

## 🧩 How It Fits into the Ecosystem
This package is a crucial part of the `RA.Utilities` ecosystem.
It sits in the **Infrastructure/Data Layer** and depends on:

* **[`RA.Utilities.Data.Abstractions`](../Abstractions/index.mdx)**:
It implements the interfaces ([`IRepositoryBase<T, TKey>`](../Abstractions/IRepositoryBase.md), [`IReadRepositoryBase<T, TKey>`](../Abstractions/IReadRepositoryBase.md), [`IWriteRepositoryBase<T, TKey>`](../Abstractions/IWriteRepositoryBase.md)) from this package.
* **[`RA.Utilities.Data.Entities`](../Entities/index.mdx)**: It works with the entity base classes defined in this package.

By using this package, you can avoid writing repetitive data access code and focus on your application's business logic,
while still maintaining a clean, decoupled, and testable architecture.

## ⚡️ In short, it helps you:

* **Accelerate Development**:
  It provides generic base classes ([`RepositoryBase`](./RepositoryBase.md), [`ReadRepositoryBase`](./ReadRepositoryBase.md), [`WriteRepositoryBase`](./WriteRepositoryBase.md)) that handle all the common CRUD
  (`Create`, `Read`, `Update`, `Delete`) operations, so you don't have to write that boilerplate code yourself.
* **Promote Clean Architecture**: By providing the implementation for the data access abstractions,
it allows your application's business logic to depend on interfaces, not on a specific data technology like ***Entity Framework Core***.
This makes your code more decoupled, maintainable, and easier to test.

## ⭕️ Core Components
The package offers several key components to achieve this:

* **[`RepositoryBase<T, TKey>`](./RepositoryBase.md)**: A full generic repository with both read and write functionality.
* **[`ReadRepositoryBase<T, TKey>`](./ReadRepositoryBase.md)**: A read-only version optimized for performance (`AsNoTracking()`), ideal for query operations in a CQRS architecture.
* **[`WriteRepositoryBase<T, TKey>`](./WriteRepositoryBase.md)**: A write-only version for add, update, and delete operations.
* **[`BaseEntitySaveChangesInterceptor`](./Interceptors/BaseEntitySaveChangesInterceptor.md)**: A `SaveChanges` interceptor that automatically maintains timestamp properties (`CreatedAt`, `LastModifiedAt`) on entities that expose them.
* **[`ServiceCollectionExtensions`](./Extensions/ServiceCollectionExtensions.md)**: One-line registration extensions (`AddRepositoryBase()`, `AddReadRepositoryBase()`, `AddWriteRepositoryBase()`).
* **[Value object converters](./Conventions/ValueObjectConverters.md)**: EF Core value converters that map `Email`, `Currency`, `SSN`, and `Money` to database columns.
* **[`MoneyConventionExtensions`](./Extensions/MoneyConventionExtensions.md)**: The `HasMoney()` convention that maps a `Money` property to two columns (decimal `Amount` + string `Currency`) as an EF Core complex property.

All repository implementations constrain their entity type to [`CoreEntity<TKey>`](../Entities/CoreEntity.md) (`where T : CoreEntity<TKey> where TKey : notnull`), so the primary key can be any non-nullable type.

By using this package, you can quickly set up a robust and well-architected data access layer for your .NET applications.

## 🛠️ Installation

You can install the package via the .NET CLI:

```bash
dotnet add package RA.Utilities.Data.EntityFramework
```

Or through the NuGet Package Manager console:

```powershell
Install-Package RA.Utilities.Data.EntityFramework
```

## 🔗 Dependencies

-   **[`RA.Utilities.Data.Abstractions`](../Abstractions/index.mdx)** (10.0.3 or later): Provides the core interfaces (`IRepositoryBase<T, TKey>`, `IReadRepositoryBase<T, TKey>`, `IWriteRepositoryBase<T, TKey>`, `IUnitOfWork`) that this package implements.
-   **[`RA.Utilities.Data.Entities`](../Entities/index.mdx)** (10.1.1 or later, transitively via the abstractions): Provides the entity base classes — [`CoreEntity<TKey>`](../Entities/CoreEntity.md) and its derivations — that the repository type parameters constrain to.
-   **[`RA.Utilities.Core.ValueObjects`](../../core/RA.Utilities.Core.ValueObjects/index.mdx)** (10.1.0 or later): Provides the `Email`, `Currency`, `SSN`, and `Money` value objects that the converters and the `HasMoney()` convention persist.
-   **[`Microsoft.EntityFrameworkCore`](https://learn.microsoft.com/en-us/dotnet/api/microsoft.entityframeworkcore)**: The underlying ORM used for the implementations.
