A centralized and consistent set of core constants for the RA Utilities ecosystem.
This package helps streamline development, improve code readability, and reduce "magic strings" and "magic numbers" by providing a single source of truth for common values.

## 🎯 Purpose

The primary goal of this package is to ensure consistency across different projects and services. By using these predefined constants, you can:

- **Avoid Typos**: Prevent hard-to-find bugs caused by typos in strings or numbers.
- **Improve Readability**: Make your code more self-documenting (e.g., `BaseResponseCode.NotFound` is clearer than `404`).
- **Simplify Maintenance**: Update a constant in one place, and the change propagates everywhere it's used.

### ✨ Key Features

- **HTTP Status Codes** — `BaseResponseCode` provides named constants for all common HTTP status codes (200–504)
- **Standardized Messages** — `BaseResponseMessages` delivers consistent, production-ready API response text
- **Semantic Response Types** — `ResponseType` is an extensible type-safe enum pattern for API outcome classification
- **HTTP Header Names** — `HeaderParameters` centralizes common header name strings for tracing, auth, and location
- **Zero Dependencies** — No external package dependencies; pairs seamlessly with `RA.Utilities.Core.Exceptions`
- **No Configuration** — Pure constants with no DI registration, no options, and no setup required


**PackageReference (csproj)**


### Hello World

The simplest possible usage — replace a magic number with a named constant:

```csharp showLineNumbers
using RA.Utilities.Core.Constants;

// Before: magic number
return StatusCode(404, "The requested resource was not found.");

// After: self-documenting constants
return StatusCode(BaseResponseCode.NotFound, BaseResponseMessages.NotFound);
```

No DI registration, no setup, no configuration. Just add the `using` directive and reference the constants.

## 🧠 Core Concepts

The package provides four static classes, each serving a distinct role in your API layer:

| Class | Role | Example |
|---|---|---|
| [`BaseResponseCode`](./BaseResponseCode) | HTTP status codes as `int` constants | `BaseResponseCode.NotFound` → `404` |
| [`BaseResponseMessages`](./BaseResponseMessages) | Human-readable response messages as `string` constants | `BaseResponseMessages.NotFound` → `"The requested resource was not found."` |
| [`ResponseType`](./ResponseType) | Semantic outcome labels using a type-safe enum pattern (`record`) | `ResponseType.NotFound` → `"NotFound"` |
| [`HeaderParameters`](./HeaderParameters) | HTTP header name strings | `HeaderParameters.XRequestId` → `"x-request-id"` |

### How they work together

`BaseResponseCode` and `BaseResponseMessages` handle the transport-level concerns (what HTTP code and what message), while `ResponseType` adds a machine-readable semantic label inside the JSON response body. `HeaderParameters` ensures header access is consistent across middleware, endpoints, and HTTP clients.

```
HTTP Response
├─ Status Code: BaseResponseCode.NotFound (404)
├─ Body:
│   ├─ responseCode: 404
│   ├─ responseType: "NotFound"    ← ResponseType record
│   └─ responseMessage: "Product with value '99' not found."
└─ Headers:
    └─ x-request-id: "abc-123"     ← HeaderParameters.XRequestId
```

### Terminology

- **Magic strings/numbers**: Hard-coded literals scattered throughout code. Replacing them with named constants improves readability and prevents typos.
- **Type-safe enum pattern**: Using a `record` instead of a C# `enum` so consuming projects can extend the set of values via inheritance. See [`ResponseType`](./ResponseType) for details.

## 📖 How-To Guides

### Return a 404 with consistent messaging

```csharp showLineNumbers
using Microsoft.AspNetCore.Mvc;
using RA.Utilities.Core.Constants;

[ApiController]
[Route("api/[controller]")]
public class ProductsController : ControllerBase
{
    [HttpGet("{id}")]
    public IActionResult GetProduct(int id)
    {
        var product = _productService.GetById(id);

        if (product == null)
        {
            // highlight-next-line
            return NotFound(BaseResponseMessages.NotFound);
        }

        return Ok(product);
    }
}
```

### Return a 400 for invalid input

```csharp showLineNumbers
[HttpPost]
public IActionResult CreateProduct([FromBody] Product newProduct)
{
    if (!ModelState.IsValid)
    {
        // highlight-next-line
        return BadRequest(BaseResponseMessages.BadRequest);
    }

    var createdProduct = _productService.Create(newProduct);
    return CreatedAtAction(nameof(GetProduct), new { id = createdProduct.Id }, createdProduct);
}
```

### Use consistent header names

```csharp showLineNumbers
[HttpGet("trace")]
public IActionResult GetTraceId()
{
    // highlight-next-line
    if (Request.Headers.TryGetValue(HeaderParameters.XRequestId, out var requestId))
    {
        return Ok(new { requestId });
    }

    return BadRequest(BaseResponseMessages.BadRequest);
}
```

## ⚙️ Configuration

This package has **no configuration options**. There is no DI registration, no `appsettings.json` entries, and no options classes. All values are compile-time `const` or `static readonly` fields — reference them directly.
