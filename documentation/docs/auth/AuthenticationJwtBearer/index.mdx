# RA.Utilities.Authentication.JwtBearer

[![NuGet version](https://img.shields.io/nuget/v/RA.Utilities.Authentication.JwtBearer.svg?logo=nuget&label=NuGet)](https://www.nuget.org/packages/RA.Utilities.Authentication.JwtBearer/)

[![Codecov](https://codecov.io/github/RedonAlla/RA.Utilities/graph/badge.svg)](https://codecov.io/github/RedonAlla/RA.Utilities)
[![Publish NuGet](https://github.com/RedonAlla/RA.Utilities/actions/workflows/publish-nuget.yml/badge.svg)](https://github.com/RedonAlla/RA.Utilities/actions/runs/19649494913)
[![GitHub license](https://img.shields.io/github/license/RedonAlla/RA.Utilities)](https://github.com/RedonAlla/RA.Utilities/blob/main/LICENSE)

`RA.Utilities.Authentication.JwtBearer` streamlines JWT Bearer authentication setup in ASP.NET Core by moving configuration out of your `Program.cs` and into `appsettings.json`. A single extension method reads your configuration, applies smart type conversions, and registers everything the framework needs — no boilerplate, no hardcoded secrets.

## 🎯 Purpose

Configuring JWT Bearer authentication in ASP.NET Core typically requires 20+ lines of setup in `Program.cs`: binding configuration sections, converting string keys to `SymmetricSecurityKey`, setting clock skew as a `TimeSpan`, wiring up authorization, and registering middleware in the correct order. This package collapses all of that into two calls:

```csharp
builder.Services.AddJwtBearerAuthentication(builder.Configuration);
// ...
app.UseAuth();
```

The configuration lives entirely in `appsettings.json`, making it environment-aware and easy to audit. This approach gives you:

- **Configuration-driven security**: JWT validation parameters (authority, audience, key material, clock skew) are managed through config files, not code — different environments can use different identity providers without rebuilding.
- **Type coercion handled for you**: `ClockSkewInSeconds` (a number) is automatically converted to a `TimeSpan`, and `IssuerSigningKeyString` (a plain string) is converted to a `SymmetricSecurityKey` with a minimum-length safety check.
- **Guaranteed callback ordering**: An optional `configureOptions` callback lets you programmatically extend or override any setting — and it always runs **last**, so your overrides always win.
- **Fail-fast validation**: If your signing key is too short for HMAC-SHA256, the app fails at startup with a clear error message — not at runtime with a cryptic token validation failure.

### ✨ Key Features

- **One-call setup** — `AddJwtBearerAuthentication()` configures authentication, authorization, and JWT Bearer options from `IConfiguration`
- **Convenience middleware** — `UseAuth()` chains `UseAuthentication()` + `UseAuthorization()` in the correct order
- **Smart type conversion** — `ClockSkewInSeconds` (double) → `TimeSpan`, `IssuerSigningKeyString` (string) → `SymmetricSecurityKey`
- **Minimum key enforcement** — Keys shorter than 32 bytes (256 bits) are rejected at startup with a descriptive error
- **Programmatic override hook** — The `configureOptions` callback runs after all config binding, guaranteeing consumer overrides take effect
- **Named-scheme aware** — Only applies to the `JwtBearerDefaults.AuthenticationScheme` scheme, leaving custom named schemes untouched

## 🧠 Core Concepts

### Configuration flow

When you call `AddJwtBearerAuthentication(configuration, configureOptions)`, the library registers a single `IConfigureNamedOptions<JwtBearerOptions>` implementation that applies settings in a fixed, documented order:

```
┌──────────────────────────────────────────────────┐
│  ConfigureJwtBearerOptions.Configure()            │
│                                                   │
│  Step 1: Bind standard JwtBearerOptions           │
│          from Authentication:Schemes:Bearer       │
│          (Authority, Audience, ValidIssuer, etc.) │
│                ↓                                  │
│  Step 2: Apply special conversions                │
│          ClockSkewInSeconds → TimeSpan            │
│          IssuerSigningKeyString → SecurityKey     │
│                ↓                                  │
│  Step 3: Invoke configureOptions callback         │
│          (user overrides — ALWAYS wins)           │
└──────────────────────────────────────────────────┘
```

This ordering guarantees that configuration files set the baseline, the library applies its smart conversions, and the consumer has the final say via the callback.

### Configuration keys

The library reads from `Authentication:Schemes:Bearer` and its children. The two non-standard keys are:

| Config Key | Type | Purpose | Default |
|---|---|---|---|
| `TokenValidationParameters:ClockSkewInSeconds` | `double` | Token expiration tolerance | `300` (5 minutes) |
| `TokenValidationParameters:IssuerSigningKeyString` | `string` | Symmetric key material for HMAC-SHA256 | `null` (not set) |

All other keys under `Authentication:Schemes:Bearer` follow the standard ASP.NET Core `JwtBearerOptions` binding — `Authority`, `Audience`, `ValidIssuer`, `ValidateLifetime`, etc.

### Terminology

- **Clock skew**: The allowed time difference between the token issuer's clock and your server's clock. Default is 5 minutes — if a token expires at 12:00, it's still accepted until 12:05.
- **Issuer signing key**: The symmetric key used to verify the token's signature. Must be at least 32 bytes (256 bits) for HMAC-SHA256.
- **`configureOptions` callback**: An optional `Action<JwtBearerOptions>` parameter on `AddJwtBearerAuthentication()`. It runs after all config binding and conversions, so you can set `Events`, override `TokenValidationParameters`, or add custom handlers.

## 📖 How-To Guides

### Use a self-issued token (no external identity provider)

Configure the key in `appsettings.json` — everything else is optional:

```json
{
  "Authentication": {
    "Schemes": {
      "Bearer": {
        "TokenValidationParameters": {
          "ValidateIssuerSigningKey": true,
          "IssuerSigningKeyString": "your-secret-key-at-least-32-bytes-long!!"
        }
      }
    }
  }
}
```

### Use an external identity provider (Azure AD, Auth0, Keycloak, etc.)

Set the `Authority` and `Audience`. The library discovers signing keys automatically via the OIDC metadata endpoint:

```json
{
  "Authentication": {
    "Schemes": {
      "Bearer": {
        "Authority": "https://login.microsoftonline.com/{tenant-id}/v2.0",
        "Audience": "api://your-client-id"
      }
    }
  }
}
```

### Tighten clock skew for stricter token expiration

Reduce the 5-minute default to something tighter:

```json
{
  "Authentication": {
    "Schemes": {
      "Bearer": {
        "TokenValidationParameters": {
          "ClockSkewInSeconds": 30
        }
      }
    }
  }
}
```

### Add custom JWT event handlers

Use the `configureOptions` callback to hook into authentication events:

```csharp showLineNumbers
builder.Services.AddJwtBearerAuthentication(builder.Configuration, options =>
{
    options.Events = new JwtBearerEvents
    {
        OnAuthenticationFailed = context =>
        {
            // highlight-next-line
            _logger.LogWarning(context.Exception, "JWT authentication failed");
            return Task.CompletedTask;
        },
        OnTokenValidated = context =>
        {
            // highlight-next-line
            _logger.LogInformation("Token validated for {Subject}",
                context.Principal?.FindFirst("sub")?.Value);
            return Task.CompletedTask;
        }
    };
});
```

### Override a config-driven setting programmatically

The callback runs **after** config binding, so you can selectively override:

```csharp showLineNumbers
builder.Services.AddJwtBearerAuthentication(builder.Configuration, options =>
{
    // Always validate lifetime, regardless of what's in appsettings.json
    // highlight-next-line
    options.TokenValidationParameters.ValidateLifetime = true;

    // Use a different key per environment
    if (builder.Environment.IsDevelopment())
    {
        // highlight-next-line
        options.TokenValidationParameters.ValidateIssuerSigningKey = false;
    }
});
```

### Validate the issuer and audience for self-issued tokens

```json
{
  "Authentication": {
    "Schemes": {
      "Bearer": {
        "TokenValidationParameters": {
          "ValidateIssuer": true,
          "ValidIssuer": "https://my-api.example.com",
          "ValidateAudience": true,
          "ValidAudience": "my-api",
          "ValidateIssuerSigningKey": true,
          "IssuerSigningKeyString": "your-secret-key-at-least-32-bytes-long!!"
        }
      }
    }
  }
}
```

### Exclude specific endpoints from authentication

The package doesn't add `[Authorize]` attributes — it only configures the JWT Bearer handler. To exclude endpoints, use the standard ASP.NET Core approach:

```csharp
app.MapGet("/health", () => "Healthy").AllowAnonymous();
```

## ⚙️ Configuration

This library reads JWT Bearer options from the `Authentication:Schemes:Bearer` section of your configuration file.

### Full reference

Here is a complete `appsettings.json` with all supported settings:

```json
{
  "Authentication": {
    "Schemes": {
      "Bearer": {
        "Authority": "https://your-identity-provider.com/",
        "Audience": "your-api-audience",
        "ClaimsIssuer": null,
        "Challenge": "Bearer",
        "TokenValidationParameters": {
          "ValidateIssuer": true,
          "ValidIssuer": "https://your-identity-provider.com/",
          "ValidateAudience": true,
          "ValidAudience": "your-api-audience",
          "ValidateLifetime": true,
          "ValidateIssuerSigningKey": true,
          "ClockSkewInSeconds": 30,
          "IssuerSigningKeyString": "your-super-secret-key-that-is-at-least-32-bytes-long!!"
        }
      }
    }
  }
}
```

:::tip

When using an identity provider with an `Authority`, you typically don't need to specify `ValidIssuer`, `ValidAudience`, or `IssuerSigningKey` — these are discovered from the OIDC metadata endpoint. The `IssuerSigningKeyString` is only needed for self-issued tokens.

:::

### Special config keys

| Key | Type | Required | Notes |
|---|---|---|---|
| `TokenValidationParameters:ClockSkewInSeconds` | `double` | No | Defaults to `300` (5 minutes). Converted to `TimeSpan` automatically. |
| `TokenValidationParameters:IssuerSigningKeyString` | `string` | No | Must be ≥ 32 bytes. Converted to `SymmetricSecurityKey` automatically. |

All other keys under `Authentication:Schemes:Bearer` are bound directly to `JwtBearerOptions` using the standard ASP.NET Core configuration binding. See the [Microsoft JwtBearerOptions documentation](https://learn.microsoft.com/en-us/dotnet/api/microsoft.aspnetcore.authentication.jwtbearer.jwtbeareroptions) for the full list of bindable properties.

### Programmatic overrides

The `configureOptions` callback gives you the final word on any option. It runs **after** all configuration binding and special conversions:

```csharp
builder.Services.AddJwtBearerAuthentication(builder.Configuration, options =>
{
    // This runs LAST — your changes always take effect
    options.TokenValidationParameters.ValidateIssuer = false;
    options.BackchannelHttpHandler = new HttpClientHandler
    {
        Proxy = new WebProxy("http://corporate-proxy:8080")
    };
});
```
